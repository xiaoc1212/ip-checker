# Claude IP 检测 · 网页与客户端

双击 `启动IP检测.vbs` 或桌面的“IP 检测工作台”。当前版本是本地 Edge 检测面板，服务只监听 127.0.0.1。

## 当前版本（2026-11-05）

当前主界面定位为原生 Claude 客户端启动预检与连接观察，不是参考网站的九宫格克隆。下面的旧版网页检测项目尚未接入当前页面，不应理解为已交付。

- 三个出口由检测窗口直接请求：国内 ip138 / ip.cn、Cloudflare 1.1.1.1 trace、Claude trace。
- 评分和归属使用同站数据源，由本机服务代查当前浏览器测得的 IP。覆盖该 IP 的网段样本明确注明来源；不能理解为当前 IP 独立实测或 Claude 官方评分。
- 浏览器 DNS 使用网页同样的随机子域名图片请求。系统 DNS 另用独立探针，放在客户端区域作参考，不混为浏览器结果。
- WebRTC 使用相同 STUN 服务，比较浏览器 Claude 出口与公网候选。无候选、探针超时、出口未取得时不判为保护已通过；也检查公网 IPv6 候选。
- 时区、语言、Cookie、WebGL、Canvas 属于检测窗口，不代表原生客户端。Canvas 为本工具自己的参考摘要，数值不要求与参考站一致。
- 不伪造地区支持结论，不把没有数据显示为绿色，也不修改时区或语言。

## 客户端专项

单独显示客户端安装、本地代理请求出口、系统/TUN 请求出口、客户端规则覆盖、强制 IPv6 系统出口探测、客户端活跃连接、尚未部署的断线保护和待验收的登录链路。IPv6 探针不是客户端本身的出口验证：成功发现公网 IPv6 会提示异常，失败、超时或无记录仍为未知，不证明防泄露。

预检启动要求客户端已安装、规则核验通过、两条工具探测路径均匹配目标 IP，且结果在 60 秒内；启动前再次读取规则。第三方评分、普通系统 DNS 地区、浏览器 WebRTC 不再单独阻止启动。

现有完整规则校验仍是保守检查：要求识别预期的进程、域名、UDP 和局域网例外规则及优先级。等价但不同的规则可能显示未核验，不能据此要求用户自动重写配置。严格路由关闭本身不判为失败；进程识别 strict 和 always 均接受。

代理请求和系统请求由检测工具发出，不是客户端自身测量。连接观察只能证明记录中的连接命中过指定代理组。没有完整登录验收，也没有操作系统级断线保护，不作账号安全保证。

## 网络配置边界

本版本不写 Clash 配置，不重载内核，不更新订阅。旧的 `configure.py --apply` 已停用，执行会直接报错；遗留规则生成器也已移除全局 TUN/DNS 改写。不要使用旧文档重新应用网络修复。

原有备份仍留在 Clash 目录；`--restore` 是手动恢复旧回执对应备份的遗留工具，会校验文件是否被后续修改，不能代替根据现状选择正确备份。

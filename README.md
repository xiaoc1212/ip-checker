# 朱玉坤工作台

2026-11-06：个人工作台四个阶段已完成，包含软件库固定、快捷方式导入、图标、场景、托盘、Alt＋Q 和备份恢复。日常操作见 [使用说明.md](使用说明.md)，新增接口见 [FEATURES_API.md](FEATURES_API.md)，基础接口见 [LAUNCHER_API.md](LAUNCHER_API.md)。

这是 Windows 本地的客户端连接预检与告警工具。桌面入口运行本机 Edge 页面，HTTP 服务只监听 127.0.0.1，使用随机路径和同源校验。网页评分与浏览器指纹请通过页面右上角的 Net.Coffee 链接查看。

## 使用

双击桌面的“IP 检测工作台”或“启动IP检测.vbs”进入快捷启动首页。点击 Claude 客户端卡片展开检测抽屉，再点击“开始环境检查”，按顺序识别客户端、核对代理规则、实测两条出口、验证证书。四项真实结果逐项更新：绿灯通过、红灯失败、黄灯待核验。全部必检满足且未过期时，右侧“启动 Claude”按钮解锁，由用户手动点击，不再在检测结束后自动启动。它不代替用户完成账号登录。

启动必检：检测器经本地代理的 Claude 出口、经系统路径的 Claude 出口、客户端预期规则和优先级、TLS 证书及相同目标出口、原生客户端安装状态。结果有效期 60 秒；启动前重读规则，并拒绝已观察到客户端连接异常的情况。

系统 IPv6、DNS、代理环境变量和证书变量为诊断参考。IPv6 探针是新加入的本地实现，不表示远端 PR 已合并：强制建立 IPv6 连接并读取 trace；能连接只证明检测器存在系统 IPv6 路径，不证明 Claude 泄露；失败或超时也不证明无旁路。这些参考项目不冒充必检绿灯。

## 新增诊断

- TLS：经本机代理建立到 claude.ai 的 HTTPS 隧道，开启证书验证，核对返回出口。证书信任来自 Python 的信任库，不是 Claude 自身的信任库。显示 TLS 版本、签发者和延迟；不跳过校验，不读取账号凭据。
- DNS：只读观察检测器能否解析 claude.ai 的 A/AAAA，不称为客户端 DNS 泄露检测。
- 环境配置：仅显示检测器进程内代理/绕过/证书变量的存在及协议类型，不展示地址、账号、口令或文件路径。读取 Windows 系统代理/PAC 的开关，不自动更改。
- 所有新增网络探针在子进程中执行，总时长限制 18 秒；超时显示未确认。不会用无结果代替通过。

## 持续观察及边界

后台串行循环读取代理规则和已识别 Claude 的活跃连接，每轮完成后等待 8 秒。页面独立显示观测时间；读取失败或结果过旧时提示未确认。它不依赖浏览器定时请求才工作。

观察仅覆盖 Mihomo 能看到并识别为 Claude 的连接。绕过 Mihomo 的连接、未识别的子进程、WSL/虚拟机和已结束的短连接可能看不到。命中住宅代理组不等于目的服务回报的 IP 已确认。没有连接时不显示通过。

这不是断线阻断：没有设置防火墙或系统级默认拒绝规则，不会杀死客户端。代理退出后会提示未确认，但不能保证在提示前没有其他流量。关闭页面后服务仍观察，使用“退出检测服务”明确停止；没有后台页面节流触发的 120 秒自动退出。

完整登录回跳和断线阻断仍未完成验收。旧规则检查仍是保守模板检查；等价的不同规则可能需要人工核验，不能为消除提示而自动重写配置。

## 配置边界

检测页面不写 Clash、DNS、路由、订阅、防火墙、系统时区和语言。独立的 client_rules.py 用于明确执行的 Claude 专用规则部署，页面不会自动调用它。旧 configure.py --apply 已停用；--restore 是受文件哈希约束的手动恢复工具，不能盲目使用旧备份。测试不会对真实配置执行恢复。

## Claude 专用规则修正

2026-11-05 已执行一批仅涉及规则的修正。独立部署命令 client_rules.py --prepare 只备份并生成/校验候选；--apply 在哈希未变化时应用已准备的规则，前后测试固定出口、TLS、国内和普通网站；失败恢复本批备份。--rollback 仅在当前文件仍与本批应用后哈希一致时恢复，避免覆盖后来修改。

本批候选必须仅改变 rules；DNS、TUN、节点、代理组和进程识别设置均进行不变性检查。备份与含凭据的候选文件留在 Clash 原目录 ipdesk-client-backups 中，不存进项目；项目 reports/client-rule-plan.json 仅保存路径、哈希、规则计数和验收摘要。旧 configure.py --apply 保持停用。

包装器遇到住宅组缺失或不再满足单成员条件时返回原配置，不使订阅生成抛错；启动器会因规则或代理组不符合预期拒绝启动。规则校验允许已证明安全的局域网 DIRECT 前置规则或已验证规则的重复项，对不能证明不冲突的前置规则仍保守拒绝，不声称识别所有等价配置。

本批规则仅在 Clash/TUN 运行时生效，不是代理退出后的系统级断线阻断。后续如更换订阅/节点仍需重新检查。固定 HTTP 住宅出口不承载公网 UDP，已识别的 Claude 公网 UDP 被拒绝，可能影响依赖 UDP 的功能；局域网与回环例外保留。


## DNS 专项采样

页面新增“执行 40 秒 DNS 专项采样”。它是独立的诊断动作，不在每次启动时自动要求管理员权限，不把历史结果用于放行启动。点击后由 Windows 请求管理员确认，使用 Python 隔离模式运行 dns_capture.py；授权取消、超时、采样失败或缺少校准都不判安全。

采样仅绑定当前活动物理 IPv4 接口的原始套接字，使用 RCVALL_IPLEVEL，不启用网卡混杂模式，不安装驱动或服务。40 秒后在 finally 中关闭套接字采样。只保存 Claude 相关域名的 DNS 元数据、计数和采样边界，不保存原始网络包、聊天内容或其他网站的查询名。为验证仪器工作，会通过物理接口发送一次随机 .invalid 域名 DNS 校准请求；校准单独标注，不计入 Claude 查询。

采样不提供进程归属、不解密 DoH/DoT，不证明 IPv6 无旁路，也不排除缓存、采样丢包或未来请求。若看到相关域名明文查询，提示出网尝试，不能自动归因于 Claude.exe。校准查询和回复均观测到、采样完成且未见不完整数据时，只显示“本次窗口未观察到相关明文 DNS 查询”，不显示“永不泄露”。

同时只读核对 Claude 当前连接是否使用住宅 HTTP 域名隧道，并检查默认上游是否带 skip-cert-verify=true。该参数代表服务器身份验证风险，不是泄露已经发生的证明。不会为消除提示而自动改动 DNS。专项采样期间暂停检测器自身的其他探针，防止其查询混入样本。

结果保存在 reports/dns-audit/，界面明确列出连接观测及采样结束时间。只展示历史采样，网络/配置变化后应重新采样；运行中的 Claude 长连接可能完全不产生新的 DNS 查询，因此单次零记录也不是全流程证明。


## 启动器界面（2026-11-05 更新）

实现为 Python 本机检测服务 + 原生 HTML/CSS/JavaScript，Edge 应用窗口呈现；没有 React/Vue/Electron 依赖。前端无需 Node 开发服务器。dashboard.css 独立维护布局，后端静态文件接口提供正确的 CSS 类型。

主界面只保留四个明确区域：左侧四步检查时间线，右侧目标出口及检测/手动启动，下方实时连接摘要，以及默认折叠的高级诊断。DNS 专项、环境变量和完整规则证据均保留在高级区域；默认 DNS 跳过证书验证及断线阻断未部署等重要限制仍通过可见提示条告知，不因折叠而隐藏。

后台检测真正按步骤执行并发送进度，前端在检测时提高轮询频率；无模拟检查时间、无定时自动亮绿。每项可展开依据，失败项自动展开原因。过期结果不能用于启动；修改目标后必须重新检查。启动按钮仍受后端同一轮次、目标、有效期和规则复核约束。

界面采用随窗口变化的字号与间距、自动换行的检查/启动布局。宽检查面板呈现两列检查卡，窄窗口改为上下排列，导航仍可访问。顶部“− / 自动 / ＋”调节界面比例（85%–140%），支持本地记忆与一键恢复自动适应；不拦截浏览器缩放快捷键。缩小时允许纵向滚动，不通过缩小全部内容来强行塞进一屏。


## 桌面全宽与订阅流量管理（2026-11-09）

- 工作台取消 1380px 居中宽度限制，使用屏幕可用宽度；Edge 桌面应用窗口默认最大化，顶栏另设“⛶ 全屏”按钮，Esc 可退出系统全屏。小屏仍保留自适应网格。
- 常用网站优先请求服务商官网 favicon，失败时仅对预设的公开网站使用 Google favicon 缓存；都不可用则退回原有本地图标。分组标题增加识别图形。公网图标首次加载需要能访问对应网站，不保证所有品牌均有高分辨率徽标。
- “订阅与网络管理”顶部显示经本机 Clash 代理实测的出口 IP、Clash 状态、整机实时流量。整机速率**不是某个机场的套餐剩余量**；出口 IP 不证明当前使用的具体机场。
- 订阅卡按“主用（手动标记）/备用/停用或未使用/未分类”分组，支持登记到期日、总流量 GB、已用 GB、关联 Clash 的代理提供者名称。所有字段按原有 `launcher-data.json` 原子落盘，不保存账号口令。
- 用户打开订阅管理或主动点击刷新时，后端通过本机 Mihomo 命名管道只读调用 `/providers/proxies`，从 `subscriptionInfo` 中仅提取 Upload/Download/Total/Expire 的数字，不返回节点、订阅 URL 或凭据；若匹配用户登记的 `provider_name`，优先用实时获取的日期和配额。数据缓存 60 秒；按钮可强制刷新。没导入 Clash 的服务可手动输入，无法获取则显示“—”/未登记。
- Clash 中已配置但尚未纳入工作台管理的订阅也在下方临时列出，点击“加入管理”即可创建对应记录。提供者名称匹配为手动关联，不宣称自动识别哪家机场正在承载流量。
- 历史数据迁移兼容原有 10 字段订阅结构；备份和恢复仍支持旧记录。修改不涉及 DNS、防火墙、分流规则和 Claude 启动门禁。
